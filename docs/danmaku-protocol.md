# 弹幕协议 v1

连接 `ws://localhost:8081/ws?room=1001`。连接固定属于该房间，省略或留空时仍使用 `lobby`；换房需要重新连接。当前尚无视频实体，房间名暂作为视频弹幕的分组标识，不校验视频是否存在或可播放。

## 发送

使用 WebSocket 文本帧，发送一个 UTF-8 JSON 对象：

```json
{"content":"你好","position_ms":12500,"color":"#ff8800"}
```

| 字段 | 约定 |
| --- | --- |
| `content` | 必填字符串，去掉首尾空白后为 1～255 个 Unicode 码点；禁止内部换行和控制字符 |
| `position_ms` | 必填非负 int64 整数，单位为毫秒；`0` 表示视频起点，不能省略或传 null |
| `color` | 可选；省略、空字符串或 null 时默认 `#ffffff`，否则要求 `#RRGGBB`，输出统一小写 |

`12500` 表示弹幕应出现在视频的第 12.5 秒。当前没有视频时长数据，尚不校验位置是否超过视频长度。Unicode 码点数不是 UTF-8 字节数，也不总等于屏幕上的字符数，例如组合 emoji 可能占多个码点。

不接受额外字段，包括客户端提供的 `id`、`room_id`、`created_at_ms` 和 `user_id`。每次发送都检查握手 Cookie 对应的 Redis 会话，`user_id` 由服务端从会话确定；房间从已建立连接确定。游客可以接收但不能发送；先登录再建立连接，登录或轮换 Cookie 后须重连，步骤见 [账号流程](accounts.md)。

`/ws` 已替换原来的任意文本、二进制原样广播协议。旧客户端需改为上述 JSON。4 KiB 消息上限仍有效；超过限制会以 WebSocket 关闭码 1009 断开连接。

## 接收

所有本房间成员（包含发送者）收到相同 JSON 文本，结构如下（值为示例）：

```json
{
  "type":"danmaku",
  "id":"server-generated-id",
  "room_id":"1001",
  "user_id":"server-authenticated-user-id",
  "content":"你好",
  "position_ms":12500,
  "color":"#ff8800",
  "created_at_ms":1793719200000
}
```

`id` 和 `created_at_ms` 在服务端校验通过后生成；后者为服务端接收时的 Unix 毫秒时间，与视频播放位置是两个概念。接收时间不保证不同消息间严格递增，随机 ID 也不表示顺序。

新发送的弹幕均带 `user_id`，广播与历史查询保持一致。旧归档没有作者，查询时省略该字段，不能据此推断作者。暂不包含用户名、头像或角色。

同样内容发送两次是两条合法事件，会生成两个 ID；同一事件在内部重试时保留原 ID。当前不提供浏览器重发去重，也没有单独的保存成功 ACK；收到广播不代表 MySQL 已完成保存。

## 错误

格式、字段或业务值不合法时，只向发送者回复：

```json
{"type":"error","code":"invalid_danmaku","message":"position_ms 必须提供，且为非负整数毫秒"}
```

错误不会进入 Kafka、Redis 或数据库，也不会广播给其他成员。未超过传输大小限制且发送队列可用时，同一连接可以改正后继续发送。错误回复同样经过客户端发送队列，由单个 `writePump` 写入；队列满或成员已被清理时退出连接，避免并发写或向已关闭 channel 发送。

未登录、已退出、会话过期或轮换时返回私有 `unauthenticated`；会话服务查询失败时返回 `auth_unavailable`。拒绝发送后保留接收能力。登录成功后应重新建立连接以携带新 Cookie。身份检查和事件发布并非原子操作，退出时已经通过检查的在途消息仍可能完成。

## 保存与迁移范围

服务端只生成一次 `Danmaku` JSON，将相同字节放入 `RoomEvent.Data`，同时用于实时广播和数据库保存；外层 `RoomEvent.ID` 与 JSON 内 `id` 一致。

`danmaku.data BLOB` 保留完整 JSON，同时在同一事务中写入 `danmaku_history` 查询表。内容和播放位置已拆列，支持按房间、播放时间范围查询，接口和回填命令见 [历史弹幕查询](history-query.md)。

已有 Kafka 队列中的旧事件仍按原始外层结构消费和保存，不会因本次协议升级被抛弃；不含正式协议字段的记录只保留归档，不出现在按播放时间查询的结果中。旧传输层的二进制测试仍保留，但原样解码器只存在于测试代码，真实 `/ws` 不提供绕过业务校验的入口。

## 验证

`TestDanmakuProtocol` 验证非法格式、未知字段、位置缺失和越界、内容长度、UTF-8、颜色、私有错误回复、错误后继续发送、同内容不同 ID，以及保存事件与广播字节一致。另有消息大小关闭测试和成员并发移除时的错误回复测试。

跨实例广播与 MySQL 停服恢复测试已改用正式 JSON，检查内容和播放位置传递，以及数据库 JSON 中的 ID 与主键一致。真实服务验证结果见 [异步持久化实验](async-persistence.md)。
